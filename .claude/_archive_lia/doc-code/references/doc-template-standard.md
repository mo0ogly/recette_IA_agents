## File Organization (Librarian Pattern)

Documents are organized by TYPE, not by creation date.
Each module gets its own directory with a consistent internal structure.

```
_alire/01_DOCUMENTATION/
+-- INDEX.md                              <- Auto-generated catalog
+-- api/                                  <- API references (type: API)
|   +-- {module}_api_en.md
|   +-- .{module}_api_en.doc-meta.json
+-- architecture/                         <- Architecture docs (type: ARCH)
|   +-- {module}_arch_en.md
|   +-- .{module}_arch_en.doc-meta.json
|   +-- diagrams/                         <- Mermaid sources
|       +-- {module}_architecture.json    <- Input descriptor
|       +-- {module}_architecture.mmd     <- Generated Mermaid
|       +-- {module}_sequence.json
|       +-- {module}_sequence.mmd
|       +-- {module}_er_model.json
|       +-- {module}_er_model.mmd
|       +-- {module}_component_tree.json
|       +-- {module}_component_tree.mmd
+-- technical/                            <- Technical docs (type: TECH)
|   +-- {module}_tech_en.md
|   +-- .{module}_tech_en.doc-meta.json
+-- user-guides/                          <- User guides (type: USER)
|   +-- {module}_user_en.md
|   +-- .{module}_user_en.doc-meta.json
+-- security/                             <- Security docs (type: SEC)
|   +-- {module}_sec_en.md
+-- specs/                                <- Specifications (type: SPEC)
|   +-- {module}_spec_en.md
+-- exports/                              <- Generated Word/PDF
|   +-- {module}_{type}_v{VERSION}.docx
+-- archive/                              <- Archived docs (NEVER deleted)
    +-- {module}_{type}_en_v{OLD_VERSION}_archived_{YYYY-MM-DD}.md
```

### Naming Convention

```
{MODULE}_{TYPE}_en.md

Examples:
  compliance_api_en.md          -> _alire/01_DOCUMENTATION/api/
  discovery_arch_en.md          -> _alire/01_DOCUMENTATION/architecture/
  cve_explorer_tech_en.md       -> _alire/01_DOCUMENTATION/technical/
  ciso_dashboard_user_en.md     -> _alire/01_DOCUMENTATION/user-guides/
  auth_middleware_sec_en.md      -> _alire/01_DOCUMENTATION/security/
  remediation_spec_en.md        -> _alire/01_DOCUMENTATION/specs/
```

### Metadata Sidecar

Every `.md` gets a `.doc-meta.json` sidecar (via `doc_classifier.py init`).
Schema: see `references/doc-classification.md` section 5.

---

## Rules for Template Usage

1. **NEVER skip mandatory sections** -- leave them empty with `{TODO: pending agent report}` only during generation, never in final output
2. **NEVER add sections not in the template** unless the module genuinely requires it (document the deviation in the recette)
3. **Conditional sections**: omit entirely if not applicable (do not leave empty headers)
4. **Diagrams**: always provide BOTH the JSON descriptor AND the .mmd source
5. **Examples**: MUST come from real code (Read tool), NEVER invented
6. **Language**: English only in .md files, English in code comments (R12)
7. **No emoji** (R10), no placeholder, no TODO in final output
8. **Archive, never delete**: when updating, archive the previous version in `_alire/01_DOCUMENTATION/archive/`

## Quick Start

```bash
# 1. Generate doc from template
/doc-code {module_name}

# 2. Initialize metadata
python3 .claude/skills/doc-code/scripts/doc_classifier.py init \
  _alire/01_DOCUMENTATION/technical/{module}_tech_en.md \
  --title "{Module} Technical Documentation" \
  --type TECH --version 1.0.0

# 3. Generate Word export
python3 .claude/skills/doc-code/scripts/generate_word_doc.py \
  _alire/01_DOCUMENTATION/technical/{module}_tech_en.md \
  --meta _alire/01_DOCUMENTATION/technical/.{module}_tech_en.doc-meta.json \
  -o _alire/01_DOCUMENTATION/exports/{module}_tech_v1.0.0.docx

# 4. Generate INDEX
python3 .claude/skills/doc-code/scripts/doc_classifier.py index _alire/01_DOCUMENTATION/ -o _alire/01_DOCUMENTATION/INDEX.md
```
