# Multi-Scripts Strategy

## Phase 2: Multi-Scripts Analysis (INTELLIGENT DECISION)

Before creating scripts, analyze existing YAML rules to determine if multiple specialized scripts are needed.

### Step 2.0: Automatic ObjectClass Analysis

```bash
# Analyze existing YAML rules
Grep: "ObjectClass:" path=lia_rules/rule_analysis/{TECHNOLOGY}/ glob=*.yml output_mode=content

# Extract all distinct ObjectClass values
# Count usage frequency
# Identify logical groups
```

### ObjectClass Grouping Patterns

| ObjectClass Pattern | Logical Group | Suggested Script |
|---------------------|---------------|------------------|
| `*_system`, `*_version`, `*_info` | System info | `Collect-{Tech}-System` |
| `*_config`, `*_settings` | Configuration | `Collect-{Tech}-Config` |
| `*_vpn`, `*_ssl`, `*_ipsec` | VPN/Crypto | `Collect-{Tech}-VPN` |
| `*_firewall`, `*_policy`, `*_rules` | Firewall | `Collect-{Tech}-Firewall` |
| `*_ha`, `*_cluster`, `*_failover` | High Availability | `Collect-{Tech}-HA` |
| `*_cis`, `*_compliance`, `*_audit` | Compliance | `Collect-{Tech}-CIS` |
| `*_users`, `*_accounts`, `*_auth` | Authentication | `Collect-{Tech}-Users` |
| `*_gpo`, `*_ad_*` | Active Directory | `Collect-{Tech}-GPO` |

### Step 2.1: Strategic Decision

**Automatic thresholds:**

| Distinct ObjectClasses | Strategy | Action |
|------------------------|----------|--------|
| 1-3 | Quick Start | 1 simple script (Phase 2a) |
| 4-8 | Multi recommended | Propose 2-3 specialized scripts |
| 9-15 | Multi mandatory | Propose 3-5 specialized scripts |
| 16+ | Complex architecture | Propose 5+ scripts (AD/Ubuntu style) |

**Example FORTIGATE (122 rules):**

```
YAML rules analysis:
  - fortios_system: 45 rules
  - fortios_config: 35 rules
  - fortios_vpn: 12 rules
  - fortios_firewall: 15 rules
  - fortios_ha: 8 rules
  - fortios_antivirus: 4 rules
  - fortios_logging: 2 rules
  - fortios_admin: 1 rule

Total: 8 distinct ObjectClasses -> MULTI RECOMMENDED

Generate all 4 specialized scripts? [Y/n]
```

### Step 2.2: Quick Start Mode (default - 1-3 ObjectClasses)

If 1-3 distinct ObjectClasses OR user declines multi:
- Continue with Phase 2a (1 simple script)
- Document multiple ObjectClasses in OBJECTCLASS_REFERENCE.md
- Add note "Quick Start - Additional scripts possible"

### Step 2.3: Multi-Scripts Mode (4+ ObjectClasses with agreement)

If 4+ distinct ObjectClasses AND user agrees:
- Generate N specialized scripts (N = 2 to 5+)
- Create N sample_output_{group}.json
- Create 1 orchestrator RUN_ALL_COLLECTORS.ps1
- test_collect.sh validates all scripts
- OBJECTCLASS_REFERENCE.md documents ObjectClass to Script mapping

### Multi-scripts file structure

```
scripts/collect/{technology}/
    Collect-{Tech}-System.ps1           # Script 1
    Collect-{Tech}-Config.ps1           # Script 2
    Collect-{Tech}-VPN.ps1              # Script 3 (if applicable)
    Collect-{Tech}-HA.ps1               # Script 4 (if applicable)
    sample_output_system.json
    sample_output_config.json
    sample_output_vpn.json
    sample_output_ha.json
    RUN_ALL_COLLECTORS.ps1              # Orchestrator
    test_collect.sh                     # Tests all scripts
    COLLECTION_RESEARCH.md
    OBJECTCLASS_REFERENCE.md            # Mapping included
```

## Batch Mode (Agent Waves)

When TODO list contains 5+ scripts to create, use wave mode:

```
Wave 1 (5 parallel agents):
  Agent 1: /create-collect-script {TECH1} windows
  Agent 2: /create-collect-script {TECH2} linux
  Agent 3: /create-collect-script {TECH3} windows
  Agent 4: /create-collect-script {TECH4} api
  Agent 5: /create-collect-script {TECH5} linux

-> Wait for all results
-> Validate each script with the 5 gates
-> Valid scripts: mark DONE in collect_scripts_status.json
-> Invalid scripts: mark REVIEW with reason
-> Launch Wave 2 with the next 5 scripts
```

**Source of truth for batches:**
- `_alire/tracking/collect_scripts_status.json` - status TODO/IN_PROGRESS/DONE/REVIEW
- `_alire/temp/TODO_collect_scripts.md` - prioritized list (generated by audit_missing_collect_scripts.py)
